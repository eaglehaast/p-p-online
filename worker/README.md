# Ретранслятор Paper Wings

Маленький сервер, через который два игрока видят ходы друг друга. Игру он не знает: для
него пакет — непрозрачный конверт, который надо передать второму и, в двух случаях,
придержать.

Запустить его можно двумя способами: **на своём компьютере** — попробовать прямо сейчас,
ничего не устанавливая, — или **в облаке**, чтобы играть, не держа компьютер включённым.
Комнату в обоих случаях крутит один и тот же `room.js`.

## Попробовать сейчас: сервером работает твой компьютер

```sh
node worker/local-server.js
```

Всё. Он раздаёт и саму игру, и ретранслятор на одном порту, и печатает две готовые ссылки
— себе и другу. Ставить ничего не надо: WebSocket написан руками (`ws-frames.js`) именно
поэтому.

```
Комната: barsuk

  себе:  http://localhost:8080/?room=barsuk&seat=blue&relay=auto
  другу: http://192.168.1.5:8080/?room=barsuk&seat=green&relay=auto   (если он в той же сети)
```

Друг в той же сети (дома, в гостях) откроет вторую ссылку — и всё работает.

**Через интернет** его компьютер к твоему сам не пробьётся: нужен туннель. Проще всего
`cloudflared`, он не требует аккаунта:

```sh
cloudflared tunnel --url http://localhost:8080
```

Он выдаст адрес вида `https://что-то.trycloudflare.com` — и ссылка другу станет
`https://что-то.trycloudflare.com/?room=barsuk&seat=green&relay=auto`.

`relay=auto` значит «ретранслятор там же, откуда открыта страница». Поэтому одна и та же
ссылка верна и по локальной сети, и через туннель: адрес сокета выводится сам, включая
`wss://` для `https`.

Минус у этого способа один, зато существенный: пока твой компьютер выключен, играть
нельзя. Для этого и нужен второй способ.

## Зачем он вообще нужен

Даже «прямое» соединение между двумя браузерами (WebRTC) начинается с того, что кто-то
третий сводит их вместе: браузеры не умеют находить друг друга в интернете сами. Раз
посредник неизбежен, проще сделать его же и почтальоном — тем более что игра пошаговая и
переслать надо один пакет на ход, а не поток кадров.

## Сколько это стоит

Бесплатно, с большим запасом. На free-плане Cloudflare даёт 100 000 запросов в сутки и
313 000 ГБ·с длительности. Пошаговая партия — это десятки пакетов, а между ходами комната
**спит**: режим hibernation сохраняет соединения, выгружая объект из памяти, и время сна
не тарифицируется. Именно ради этого в коде `acceptWebSocket`, а не `accept`.

Одно условие: на free-плане Durable Objects бывают только на SQLite, поэтому в
`wrangler.toml` стоит `new_sqlite_classes`, а не `new_classes`. С `new_classes` деплой
откажет с ошибкой 10097.

## Развернуть

```sh
cd worker
npx wrangler deploy
```

Wrangler попросит войти в аккаунт Cloudflare и выдаст адрес вида
`https://paper-wings-relay.<аккаунт>.workers.dev`.

Дальше впиши его в `script.js`, в `ONLINE_RELAY_URL`, заменив `https://` на `wss://`:

```js
const ONLINE_RELAY_URL = "wss://paper-wings-relay.<аккаунт>.workers.dev";
```

Проверить, не трогая код, можно и через ссылку: `?relay=wss://...` перебивает эту
настройку.

## Ссылки для игры

Создатель комнаты — синий; его настройки становятся правилами партии.

```
https://<сайт>/?room=barsuk&seat=blue     — себе
https://<сайт>/?room=barsuk&seat=green    — другу
```

Имя комнаты — любое, лишь бы у двоих совпало. В телеграм-версии его отдаст `start_param`
мини-приложения.

Без `?relay=` и без заполненного `ONLINE_RELAY_URL` игра работает через `BroadcastChannel`,
то есть между двумя вкладками одного браузера. Это не заглушка, а рабочий режим: на нём
удобно проверять всё остальное, не поднимая сервер.

## Что комната помнит

Ровно два последних пакета, и оба — чтобы вернувшийся после обрыва мог продолжить:

* `settings` — настройки создателя комнаты;
* `state` — последний снимок партии.

Оба лежат в хранилище объекта, а не в памяти: сон память не переживает.

## Что где лежит

| файл | что это |
| --- | --- |
| `room.js` | логика комнаты: места, пересылка, что придержать. Ни строчки про WebSocket |
| `index.js` | Worker и Durable Object — провода для облака |
| `local-server.js` | игра и ретранслятор на своём компьютере — провода для «попробовать» |
| `ws-frames.js` | кадры WebSocket руками, чтобы локальный сервер не требовал зависимостей |

Разделено так не ради красоты: облако из тестов не поднять, а `room.js` — можно, и её
проверяет `scripts/smoke-online-relay.js`. Разбор кадров — единственное место, где ошибка
не падает, а тихо превращается в мусор, поэтому у него свой тест,
`scripts/smoke-local-server-frames.js`.
