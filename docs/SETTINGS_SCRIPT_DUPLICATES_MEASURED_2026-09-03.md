# Совпадающие имена в settings.js и script.js — замеры (2026-09-03)

`index.html` грузит три классических скрипта подряд: `maps.js`, `settings.js`, `script.js`.
У `settings.js` и `script.js` **27 общих имён функций**, и у **15** из них тела различаются.
Выглядит как повторение той истории, что стоила нам динамита и мин, — но это не она.
Здесь только измеренное.

## Главное: перекрытия нет, и вот почему

`settings.js` и `maps.js` **целиком завёрнуты в IIFE**. Их функции живут в своей области и
на `window` не попадают. Проверено в браузере: функции, которые есть только в
`settings.js`, на `window` равны `undefined`, а функции `script.js` — на месте.

```
только в settings.js:                на window
  clampRangeStep                       undefined
  getPendulumAngle                     undefined
  setupAccuracyCrackWatcher            undefined
  clampAccuracyIndex                   undefined

только в script.js:
  rebuildCollisionSurfaces             function ✓
  distancePointToSegment               function ✓
```

Значит совпадение имён между файлами ничего не подменяет: это **две независимые копии**,
каждая обслуживает свой экран. `settings.js` зовёт свои, `script.js` — свои.

> Первая редакция теста `smoke-no-duplicate-function-names.js` утверждала обратное — что
> `script.js` грузится последним и его версии побеждают «включая вызовы из остальных
> файлов». Это было неверно; текст исправлен.

Отсюда следует настоящий инвариант: **пока обёртка на месте, дубли безвредны.** Уберут её
— 27 имён столкнутся в тот же миг, молча, и побеждать начнёт `script.js`. Теперь обёртка
проверяется тестом.

## Прицельная математика: расхождений нет

Копии `getSpreadAngleDegByAccuracy`, `getAimingSpreadScale`, `clampAimingPercent`,
`normalizeAimingTuning`, `getActiveAimingTuning` прогнаны бок о бок на всех 101 значении
точности и на мусорных входах.

```
точность   settings.js   script.js   разница
   0%           25            25         0
  20%        17.9375       17.9375       0
  50%       9.921875      9.921875       0
  80%            5             5         0
 100%            0             0         0

максимальное расхождение по всем 101 значению: 0
нештатные входы (undefined, null, NaN, -50, 150, "70", Infinity): совпало везде
normalizeAimingTuning на мусоре: совпало везде
```

Различия в тексте есть, но они в **недостижимых запасных ветках**: `script.js` при
неконечном `spreadAtReferenceDeg` считает `MAX_SPREAD_DEG * …`, а `settings.js` берёт
значение из `AIMING_TUNING_DEFAULTS`. До этих веток дело не доходит: `getActiveAimingTuning`
прогоняет настройку через `normalizeAimingTuning`, после чего все поля конечны.

Так же безобидны и остальные «расхождения» этого куста: `sharedSettings` против
`settings` — это один и тот же объект (`const settings = sharedSettings;` в `script.js`),
`??` против `||` в `getPointerClientCoords` — разница только на falsy-но-не-nullish, чем
объект касания быть не может.

## Про наследие в названиях

`aimingAmplitude` — старое имя. Когда-то настройка задавала амплитуду отклонения в
градусах; сейчас под этим именем лежит **процент точности**, шкала противоположная:

```
DEFAULT_SETTINGS.aimingAmplitude = 80     // это 80% точности, а не 80 градусов
```

Само поведение согласовано (обе копии читают одно и то же и считают одинаково), но имя
вводит в заблуждение и стоит переименования — отдельной задачей, потому что оно сохраняется
в настройках игрока.

## Настоящая разница: две системы щипкового зума

Вот что действительно продублировано не только именем.

Оба файла **вызывают свою установку обработчиков при загрузке**:

```
settings.js:217  installPinchExitOnGameplayInput();
settings.js:316  installTouchPinchZoom();
script.js:53292  installPinchExitOnGameplayInput();
script.js:53448  installTouchPinchZoom();
```

Оба вешают слушатели на `window` с `capture: true`, и оба пишут `transform` **в один и тот
же элемент**: `settings.js` создаёт `#uiFrameInner` (он грузится раньше), `script.js`
находит уже существующий.

Состояния при этом раздельные: у `settings.js` свои `pinchActive`, `pinchScale`,
`pinchPanX/Y`; у `script.js` — `window.PINCH_ACTIVE` и свои же поля.

Замер синтетическим щипком на мобильном профиле (наблюдатель за атрибутом `style`):

```
элементов #uiFrameInner на странице:        1
записей в transform за один щипок:         11
различных значений:                         9
```

То есть в начале жеста и на сбросе пишут **обе** системы, дальше ведёт одна. Видимого
поломанного поведения в этом прогоне не наблюдалось: масштаб рос ровно (1.75 → 7) и
корректно сбросился в 1, ошибок в консоли нет.

**Вывод честный:** дублирование настоящее, поломки не показано. Сводить две системы в одну
стоит, но это отдельная задача с риском задеть зум на одном из экранов, а не побочная
правка.

## Чем мерить повторно

- утечка в глобальную область — открыть страницу и посмотреть `typeof window.<имя>` для
  функций, которые есть только в `settings.js`;
- прицельная математика — извлечь обе копии в `vm` и прогнать по точности 0…100;
- щипок — `MutationObserver` на `style` у `#uiFrameInner` плюс синтетические `TouchEvent`;
  считать записи **по одной на запись мутации**, иначе наблюдатель их пакует и счёт врёт.

Автоматическая защита — `scripts/smoke-no-duplicate-function-names.js`: одно имя на файл,
обёртка у `settings.js` и `maps.js` на месте, новых межфайловых совпадений не появляется.
