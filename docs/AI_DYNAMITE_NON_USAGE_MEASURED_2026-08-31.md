# Почему ИИ почти не пользуется динамитом — замеры (2026-08-31)

Предыдущий разбор на эту тему — `AI_INVENTORY_NON_USAGE_ANALYSIS_2026-04-26.md` — состоял
из пяти гипотез без проверки. Здесь только измеренное: живая партия против компьютера,
включённый журнал решений, счётчики на функциях. Ни одной догадки, которую не подтвердили
бы цифрами.

Невидимость разобрана и починена отдельно (см. `shouldAiUseInvisibilityForSelectedPlan` и
`scripts/smoke-ai-invisibility-rule.js`). Здесь — только динамит, к нему правок пока нет.

## Как мерили

Партия против компьютера, ИИ каждый ход выдавали по 3 динамита (`giveItem`), десять ходов.
Счётчики ставились обёртками на `logDynamiteDebug` и `findAiDynamitePathOpeningOpportunity`.

## Что вышло

```
динамита выдано:                          30
поиск возможностей вызван:                 7   ← меньше одного раза за ход
из них нашли что-то:                       2
дошло до оценки плана:                     4
установлено зарядов:                       0
```

Все четыре оценки отклонены с одной причиной: `no_fuel_for_safe_return`.

## Причина первая: динамит — добавка, а не план

`findAiDynamitePathOpeningOpportunity` вызывается ровно из двух мест, и оба — **после**
того, как план уже выбран; оба передают `planTarget`, то есть цель этого плана. Найти их
можно по строке `dynamiteCharges > 0 ? findAiDynamitePathOpeningOpportunity(` — номера
строк здесь намеренно не указаны, они устаревают быстрее текста.

Внутри функции стоит явное ограничение (комментарий в коде):

> CRITICAL: when the caller passes the actual plan target, restrict opportunity to that
> single target. Without this, the function used to iterate ALL alive enemies / cargo /
> flags / base, find the first BLOCKED one, and propose dynamite for IT — which often had
> nothing to do with the plane's plan.

Сужение сделано осознанно и чинило настоящий баг: заряд ставили к одной цели, пока самолёт
летел к другой. Но получилась замкнутая петля:

- планировщик выбирает цель, до которой **есть** дорога;
- потом у выбранной цели спрашивают, не мешает ли кирпич;
- кирпич не мешает, потому что цель и выбрали за проходимость.

Ветка перебора всех целей (враги, грузы, флаги, база) в функции осталась, но живого
вызова без `planTarget` нет — то есть она недостижима.

## Причина вторая: сцепка с топливом

Ищется по строке `no_fuel_for_safe_return`, внутри оценки плана с динамитом (там же
рядом — `dynamite_augmented_plan_flag_target_skipped`). Правило узкое, только цель-флаг:
если посадка после захвата флага попадает под ответный удар, а топлива в инвентаре нет,
план отбрасывается.

Проверено опытом — тот же прогон, но ИИ выдавали ещё и топливо:

```
                        только динамит      динамит + топливо
отказов no_fuel                    4                      0
dynamite_about_to_place            0                      2
dynamite_launch_replanned          0                      2
```

То есть при прочих равных наличие топлива включает динамит. Само правило разумно (без
топлива самолёт не вернётся), но в связке с первой причиной оно добивает и без того
редкие случаи.

## Что предлагается делать

Порядок важен: вторая правка без первой почти ничего не изменит, потому что до оценки и
так почти не доходит.

1. **Дать планировщику рассматривать заблокированную цель вместе с динамитом как один
   план.** Сейчас заряд прикручивается к готовому решению; надо, чтобы «цель за стеной +
   заряд» участвовало в выборе наравне с обычными ходами и проигрывало или выигрывало по
   счёту, а не отсеивалось заранее.

   Возвращать перебор всех целей «как было» **нельзя** — это вернёт тот самый баг с
   зарядом не туда. Связь «заряд ↔ цель этого же плана» обязана сохраниться.

2. **Пересмотреть запрет по топливу для цели-флага.** Возможные смягчения: считать
   безопасным возврат не только по топливу, но и по дальности до своих; либо разрешать
   размен, когда флаг решает партию по очкам.

## Чем мерить повторно

Обёртки, которыми снимались цифры выше (воспроизводятся в браузере через протокол
отладки):

- `logDynamiteDebug` — считать записи по `reason`, там вся воронка;
- `findAiDynamitePathOpeningOpportunity` — считать вызовы и долю непустых ответов;
- расход из `inventoryState[AI_PLAYER_COLOR]` до и после хода — фактические установки.

Порог «работает» для проверки будущей правки: динамит должен ставиться **без выдачи
топлива**, и заметно чаще нуля установок за десять ходов.
